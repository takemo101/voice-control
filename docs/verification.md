## 検証の入口

| 目的 | コマンド | 何も操作しない |
|---|---|---|
| 単体テスト（43 件） | `just test` | ○ |
| PC 操作の当たり率（固定した画面） | `just eval`（`corpus/plans.tsv`）。候補・説明文・ゲートを変えたら回す | ○ |
| 前の指示の効果 | `vc eval-context corpus/followups.tsv` | ○ |
| 位置情報の効果 | `vc eval corpus/plans.tsv --no-location`（あり・なしを比べる） | ○ |
| 音声経由 | `just eval` に `SPEAK=1`（`say` → 文字起こし） | ○（音声は合成） |
| 言語モデルとの比較 | `vc eval corpus/plans.tsv --llm` | ○ |
| 分け方の比較 | `vc decompose "<発話>"` | ○ |
| トリガーが届くか | `vc hotkey-check` | ○（マイクは使わない） |
| スキルの実行 | `vc run "<依頼>"`（自作ウィンドウ `just fixture` を対象にしたスキル） | **操作する**（自作ウィンドウだけに向ける） |

**検証は、自作のウィンドウ（`Fixture`）と、自作の音声（`say`）で行う。** 利用者の実行中のアプリ・設定を操作しない。画面の内容・文字起こしを、記録（ファイル・文書）に残さない。コーパス（`corpus/`）は、自作の文だけ。

## コーパスの扱い

- `corpus/plans.tsv`（97 文）：`snapshot<TAB>期待<TAB>発話`。期待は `open:` `click:` `type:` `press:` `scroll:` `window:` `search:` `check:` … と `none`。`|` は、同じ結果になる操作。`@左` などは、選んだ要素の位置。
- `corpus/followups.tsv`（23 文）：前の指示の文脈。
- 画面は `corpus/snapshots/*.json`（`Fixture` を agent-desktop で撮った）。
- **コーパスは自作で、言い換えが選択肢の文面と無関係ではない。当たり率は、楽観側に偏る。** 結果を見て、コーパス・説明文を直した箇所がある（下記）。**合わせ込みを含む数字は、そう書く。**
- 評価に使った文を、同じ回で調整に使わない。使ったときは、記録に書く。

## 記録

### PC 操作の選び方（Tiny-Jev。`corpus/plans.tsv`）

| 構成 | 当たり | 備考 |
|---|---|---|
| 2 段（操作の種類 → 引数） | 35%（27/77） | 種類を選ぶ段が最も外れた |
| 種類の説明に例を足す | 34%（26/77） | 慎重にはなったが、当たりは増えず |
| **1 段（具体的な操作を全部並べる）** | 69%（53/77） | 現在の構成 |
| 同値の操作を正解に加える（※1） | 80.5%（62/77） | |
| エスケープの説明から「取り消し」を除く（※2） | 83.1%（64/77） | |
| アプリは「開く」の言い方のときだけ候補にする（※3） | 88%（68/77） | |
| 状態を変える操作 13 文を足す | 85.6%（77/90） | 足した種類は、すべて正しく選ばれた |
| 位置を指す 7 文を足す・位置あり | 83.5%（81/97） | 位置なしは 79.4%（77/97）。位置を指す 7 文だけだと、あり 6/7・なし 2/7 |
| `say` → 文字起こし経由（77 文） | 79.2%（61/77） | 文字起こしが元の文と違った文 21/77 |

- ※1 コーパスを結果を見て直した（削除ボタンと削除キーのように、両方が正しい文に別の正解を足した）。※2 説明文を結果を見て直した（取り消しが、元に戻すと衝突していた）。※3 条件の語に、コーパスの文に合わせたもの（「見たい」）がある。**いずれも、合わせ込みを含む**。
- 時間：文字から 1 発話 約 0.5 秒（候補約 100 個で、採点 6 回）。音声経由は約 1.3 秒（合成と文字起こし込み）。
- **危険な外れ**：確認なしで実行した外れが 5〜8 件（回による）。多くは、操作でない会話が、その言葉を含むため（「今日は天気がいいですね」→ 天気アプリを 99% で開く）。1 件は「これ消して」→ 元に戻す 98%。操作でない発話 11 文のうち 4〜5 文が、確認か実行へ通った。**確信度だけでは、防げない**。
- 試して、やめたこと：選んだ操作を「正しいか」とはい／いいえで確かめて、確信度にする案。当たりは 83.1% だったが、確認なしの外れが 5 → 9 件に増えた（外れにも 95〜99% の「はい」）。
- 確信度の下限を 0.55 → 0.40 に下げた：当たり 63 → 64/77、確認なしの外れは 5 件のまま。

### 前の指示を文脈に使う（`corpus/followups.tsv`、23 文）

| 構成 | 当たり | 確認なしの誤り |
|---|---|---|
| 文脈あり（前の指示に触れる言い方のときだけ） | 18/23 | 3 件 |
| 文脈なし | 9/23 | 8 件 |
| （やめた）直前の操作を常に文へ添える | 12/23 | 8 件 |

- 残る外れ：「戻して」（cmd+Z と本当に曖昧）、「さっきの取り消しを取り消して」。

### Apple の言語モデルとの比較

- **選ぶ役**（同じ 77 文・同じ画面）：当たり 31〜34/77（40〜44%）。Tiny-Jev は 68/77（88%）。操作でない発話 10 文のすべてに手を返した。「元に戻して」「エスケープ」は、安全性の判定で、出力が拒否された。→ 選ぶ役は Tiny-Jev。
- **分ける役**（`--llm-split`）：聞き違いのある長い文は、ルールより読みやすく分かれた（6 手 → 4 手）。きれいな文では、手を足したり、検索を入力に変えたりした。→ 既定はルール。
- **道具を呼ぶか**：日本語の指示だと 6 回中 1 回、英語の指示だと 6 回中 6 回。→ スキルの本文は英語。

### スキル（`vc run`。自作ウィンドウ・本番実行）

- Tiny-Jev の選択：0.11 秒。「設定ボタンを押して」→ スキルを選んだ（99.4%・95.8%）。「今日は天気がいいですね」→ どれでもない（96.1%）。
- 実行（snapshot → click の 2 コマンド）：**6/6 成功**（4.7〜6.0 秒）。
- 直す前は 2/4。原因は 2 つ：①本文に `click @a1:e7` の形の**例**がなく、モデルが名前を渡した。②agent-desktop の参照が長いランダム文字列で、モデルが写し間違えた。→ モデルには短い別名を見せ、実行の直前に、本物へ戻す。
- 初期の試作（スキルを JSON で書き、道具を 6 種類に分けていた）：4 スキル × 4 回 = 16/16（9〜12 秒）。かぎ括弧のない文字（「ねこと入れて」）は、「ねこと」を入れて全部外れた。
- 限界：自作ウィンドウと 1 つの単純なスキル。複数のスキルの取り違え・複数手のスキル・実アプリは未測定。

### 実機の確認

| 項目 | 結果 |
|---|---|
| agent-desktop の snapshot・click・type（TypeText のある欄）・scroll・press（headless） | 自作ウィンドウで動いた。アクセシビリティは許可済みだった（変更していない） |
| 音声ファイル（`say`）→ 文字起こし → 計画 → 実行 | 自作ウィンドウで確認（入力・削除キー・「ちょっと待ってね」は実行しない） |
| ホットキー（Control＋Option＋Space）・Shift の長押し | 合成したキー入力で、押した・離したが届いた。短い押下・Shift＋キーは反応なし（`hotkey-check`） |
| チェック・開閉・空にする | 自作ウィンドウで、状態が変わった。スイッチへの `toggle` は、agent-desktop が拒否した（`click` に任せる） |
| ウィンドウ操作 | 最大化は効いた。`restore` は成功を返すが、このウィンドウの大きさは戻らなかった（効果は未確認） |
| アプリを開く（Spotify） | `agent-desktop launch` は TIMEOUT で何も開かなかった。`open -a` に切り替え、ウィンドウがなければ AppleScript の `activate` で出す |
| 2 キーのキー操作（cmd+a → delete） | 2 つとも送られた（自作ウィンドウは全選択を持たず、1 文字だけ消えた） |

## 人間の確認が要るもの（AI は合格にしない）

- マイクの実録音（許可ダイアログ・実際の声での認識・遅延）。`vc listen`・`--hotkey` は、実装したが、実行していない。
- 声の「はい」による確認が、実際の声で通るか。
- 実アプリ（Safari・Chrome・Slack・Spotify など）での動き。
- Shift の長押しの使い心地・誤作動（日常のタイピング中）。
- アクセシビリティ・オートメーション・マイクの許可の流れ。
